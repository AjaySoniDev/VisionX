# Evidence-gated implementation roadmap

## Completed software work in this release

The legacy regression, modular pipeline, shared numerical API, strict artifact/resume controls, exact dependency locks and executable evaluation now have retained verification/evidence. Cached fixture and generated-vector baselines are actually run. Read recorded local checks rather than inferring hosted CI success.

## Next scientific gate

Collect documented independent camera sessions for the bounded route task; annotate events; freeze development/calibration/test splits; calibrate operating thresholds only on calibration data; compare fair methods and report coverage, accepted errors, unknown false acceptance, failures and condition variation. The current diagnostics do not complete this gate.

## Mobile route integration gate

The team-reported capture/Android YOLOv8s/TTS path already exists in the current presentation account. The remaining task is VXN route integration: exact descriptor/ranking parity, causal progress, bounded evidence, direction/timing contracts, measured sustained resources and explicit freshness/fault recovery. Do not relabel live detections as route guidance.

## Sensor and output gate

Use actual VL53L0X measurements under a defined limited proximity policy. Add Pi-connected IMU only after acquisition, axes, calibration, synchronization and independent event testing; compare visual-only, IMU-only and fused evidence. Implement separate route/proximity/fault channels and cancellation of stale cues with stop/recovery tests.

## User/deployment gate

After technical failure handling and a reviewed physical setup, conduct accessible, consenting supervised co-design alongside normal mobility aids. Measure comprehension, wrong turns, interventions, workload, preference and support/enrollment effort. Validate complete costs and buyer need before any institutional pilot/commercial claim. Broader topologies and general navigation require new methods and separate evidence.
